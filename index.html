Subscription & Credits

Your institution operates on a subscription model that controls how many students you can register and how many enrollments you can create.

How Subscriptions Work

Student Slots

Each plan has a max_students limit. Every new student account created (by staff or via API) consumes one slot. If all slots are used, no new students can be registered until the plan is renewed or a new plan is added.

Students Used 234 / 500

Enrollment Slots

Each plan has a max_enrollments limit. Each time a student is enrolled in a course instance, one slot is consumed. A single student taking 3 courses uses 3 enrollment slots.

Enrollments Used 876 / 2000

Stackable Plans

Multiple plans can be active simultaneously. When one fills up, usage spills to the next available plan automatically.

Time-Bound

Each plan has a start and expiry date. Expired plans stop accepting new usage, but existing students/enrollments remain active.

Unlimited Option

A value of 0 for max_students or max_enrollments means unlimited — no cap enforced for that metric.

Burn Rate (visible in Staff Console)

The Staff Console shows a burn rate indicator — how fast your enrollment slots are being consumed and how many days remain at the current rate. This helps you plan renewals before running out.

Click "Generate New Key" — choose a label (e.g., "Production SIS"), select scopes, and optionally set an expiry date.
Copy the key immediately — it's shown only once. The key format is tldsk_ followed by 48 hex characters.
Share with your developer — they'll use it in the X-API-Key header for all API requests.

Security: API keys are hashed (bcrypt) in the database — nobody (including system admins) can see the full key after generation. If compromised, revoke it immediately and generate a new one.

Developer Portal

The External API lets your Student Information System (SIS) talk to the LMS programmatically — create accounts, enroll students, pull grades, and check certificates.

Getting Started as a Developer

Get an API key — ask your institution's staff to generate one from the API Keys module in the dashboard. They'll give you a key like tldsk_a1b2c3...
Visit the Developer Portal — go to /developer on the LMS domain. This page has full documentation and an interactive "Try It" feature.
Test with /ping — send a request to verify your key works: GET /api/v1/external/ping with header X-API-Key: your_key
Build your integration — use the endpoints to sync students, enrollments, grades, and certificates between your SIS and the LMS.

API Integration Overview

All external API endpoints live under /api/v1/external/ and require the X-API-Key header.

Example: Create a Student Account

curl -X POST https://your-lms.com/api/v1/external/accounts \
  -H "X-API-Key: tldsk_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "student@example.com",
    "full_name": "Juan Dela Cruz",
    "password": "SecurePass123!",
    "uli": "ULI-2026-0001234"
  }'

Example: Enroll a Student

curl -X POST https://your-lms.com/api/v1/external/enrollments \
  -H "X-API-Key: tldsk_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": 45,
    "course_instance_id": 12
  }'

Example: Get Student Grades

curl -X GET https://your-lms.com/api/v1/external/grades/student/45 \
  -H "X-API-Key: tldsk_your_api_key_here"

Authentication & Security

API keys are institution-scoped — you can only access data within your own institution.

Key Format

tldsk_ + 48 hex characters (54 total)

Sent via X-API-Key header on every request.

Institution Scoping

Every query is filtered to your institution. There is no way to access another institution's students, courses, or enrollments.

Scopes

Keys have specific permissions (e.g., accounts:read, enrollments:write). The staff who generates the key selects which scopes to grant.

Quota Enforcement

API operations respect your subscription limits. Creating a student or enrollment via API consumes slots just like the web UI.

Security & Privacy

The platform is built with enterprise-grade security from the ground up.

JWT Authentication

Stateless tokens with 24-hour expiry. No sessions stored on server.

BCrypt Password Hashing

All passwords hashed with 12 rounds. Never stored in plaintext.

XSS Prevention

All HTML content sanitized with nh3 library before storage.

Rate Limiting

Login: 5/minute per IP. API: 120 GET, 60 POST per minute per key.

Institution Isolation

Complete data isolation between institutions. Staff cannot see other institutions' data.

Audit Logging

All admin/staff actions and API requests logged with IP, timestamp, and details.

Frequently Asked Questions

What happens when our subscription runs out of student slots?
No new student accounts can be created until your plan is renewed or a new plan is added by the platform administrator. Existing students and enrollments remain fully functional.
Can a student be enrolled in multiple courses?
Yes. Each enrollment in a different course instance consumes one enrollment slot. The same student can take as many courses as your plan allows.
Can teachers create or edit course content?
Teachers have read-only access to course content. Course creation and content editing is done by the platform admin or content creators (with admin/developer role).
Is there a mobile app?
The platform is a responsive web application that works on any modern mobile browser. No native app installation required — simply open the URL in Chrome, Safari, or Firefox on your phone.
How does the API quota work with our subscription?
API operations follow the exact same subscription limits as the web interface. Creating a student via API consumes one student slot, creating an enrollment consumes one enrollment slot. The oldest active plan is consumed first (spillover to next plan when full).
What happens if a student fails all assessment attempts?
The student is flagged as "at risk" in the teacher's student tracker. Staff or teachers can then decide to reset attempts (by admin intervention) or provide additional support. The enrollment remains active.
How do I get support?
Contact your institution's staff or the platform administrator. For technical/API issues, developers can reference the interactive documentation at /developer.
